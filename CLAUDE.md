# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Space Invaders clone built in **Unity 6000.6.7f1** (URP 17.6, new Input System, TextMesh Pro UI). There is a single scene, `Assets/Scenes/SampleScene.unity`, and the only build profile is `Assets/Settings/Build Profiles/Web - Desktop - Development.asset` (WebGL).

## Building / running

There is no CLI build script; the project is opened, played, and built from the Unity Editor. C# compilation happens inside Unity. `Assembly-CSharp.csproj` and `SpaceInvaders.slnx` are generated by Unity for IDE IntelliSense only; don't edit them by hand. There are no test assemblies yet, although `com.unity.test-framework` is installed. If tests are added, run them headlessly like this:

```
Unity.exe -batchmode -projectPath . -runTests -testPlatform EditMode -testResults results.xml
```

## Architecture

All gameplay scripts sit flat in `Assets/` next to their prefabs and materials. They use the `[Header("Inscribed")]` / `[Header("Dynamic")]` inspector-section convention: Inscribed means set in the Inspector, Dynamic means set at runtime.

- **AlienFleet** (placed in the scene) spawns a 10×3 grid of `Alien` prefabs in `Start()` and keeps them in the `aliens` list. In `FixedUpdate` it moves every alien by transform. When the fleet hits ±16 on x it reverses direction and moves down for `downTime` seconds (via `Invoke`). Each frame it pushes `aliens.Count` into the `AlienCounter` UI.
- **Alien** fires `AlienBullet`s at random (per-FixedUpdate chance plus a cooldown). In `OnCollisionEnter` it removes itself from `fleet.aliens`, then destroys itself and whatever hit it. Any code that destroys aliens must also remove them from `fleet.aliens`, or the fleet loop will touch destroyed objects.
- **Spaceship** reads `Keyboard.current` directly: arrow keys move it, space fires a `Dart`. `InputSystem_Actions.inputactions` exists but nothing uses it.
- **Dart** / **AlienBullet** move by transform in `FixedUpdate` and destroy themselves once off-screen (y > 10 / y < -10). Dart has no collision handler; the Alien it hits destroys it. AlienBullet destroys itself and whatever it hits, including the Spaceship. There is no game-over or lives logic.
- **AlienCounter** is on a TMP text object under the scene's Canvas and displays the `score` field.

### Collision model

Collision filtering depends on **physics layers** set in `ProjectSettings/TagManager.asset` and the layer collision matrix in `ProjectSettings/DynamicsManager.asset`, not on code checks:

| Layer (index) | Used by | Does not collide with |
|---|---|---|
| Spaceship (6) | Spaceship prefab (kinematic RB) | Bullet |
| Alien (7) | Alien prefab | Alien_Bullet |
| Bullet (8) | Dart prefab | Spaceship |
| Alien_Bullet (9) | AlienBullet prefab | Alien |

All moving objects use non-trigger colliders and Rigidbodies with gravity off, and they are moved by setting `transform.position`. A new projectile or entity type needs a layer and matrix entries, or it will collide with everything.

## Editing Unity assets

`.prefab`, `.unity`, `.asset`, and `.mat` files are YAML and are hidden in VS Code by `.vscode/settings.json`. Scene and prefab wiring, such as `AlienFleet.alienPrefab` and `alienCounter`, uses GUID references from `.meta` files. Always keep a `.meta` file with its asset, and don't regenerate GUIDs. Prefer making wiring changes in the Editor over editing the YAML by hand.
