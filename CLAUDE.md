# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Space Invaders clone built in **Unity 6000.6.7f1** (URP 17.6, new Input System, TextMesh Pro UI). There is a single scene, `Assets/Scenes/SampleScene.unity`, and the only build profile is `Assets/Settings/Build Profiles/Web - Desktop - Development.asset` (WebGL).

## Building / running

There is no CLI build script; the project is opened, played, and built from the Unity Editor. C# compilation happens inside Unity. `Assembly-CSharp.csproj` and `SpaceInvaders.slnx` are generated by Unity for IDE IntelliSense only; don't edit them by hand. To check that scripts compile without the Editor, run `dotnet build Assembly-CSharp.csproj` with output redirected outside the repo (`-p:OutputPath=... -p:BaseIntermediateOutputPath=... -p:IntermediateOutputPath=...`). The csproj lists `.cs` files explicitly, so new scripts aren't included until Unity regenerates it. Outside Unity you'll also see CS0649 on `[SerializeField]` fields, which Unity's compiler suppresses. There are no test assemblies yet, although `com.unity.test-framework` is installed. If tests are added, run them headlessly like this:

```
Unity.exe -batchmode -projectPath . -runTests -testPlatform EditMode -testResults results.xml
```

## Architecture

All gameplay scripts sit flat in `Assets/` next to their prefabs and materials. They use the `[Header("Inscribed")]` / `[Header("Dynamic")]` inspector-section convention: Inscribed means set in the Inspector, Dynamic means set at runtime.

- **GameManager** (singleton, `GameManager.Instance`) owns game flow: `LevelCleared()`, `GameOver()` and `PlayerHit()`, which costs a life and ends the game at 0. It raises `StateChanged` and `LivesChanged` events. UI such as `LivesDisplay` subscribes in `Start` and unsubscribes in `OnDestroy`, keeping its own reference to the manager it subscribed to. Ending a level sets `Time.timeScale = 0`; `NierScreens` shows the matching screen. Gameplay scripts report events to it rather than deciding outcomes themselves, and they null-check `Instance` so the scene still runs without one.
- **AlienFleet** (placed in the scene) spawns a grid of `Alien` prefabs (size from the current LevelData) in `Start()` and keeps them in a private `List<Alien>`. In `FixedUpdate` it moves every alien by transform. When the fleet hits ±16 on x it reverses and steps down for `downTime` seconds (via `Invoke`). `RemoveAlien(Alien)` updates the `AlienCounter`, recalculates speed and fire rate (both rise as aliens die), and calls `GameManager.LevelCleared()` when the list is empty. The fleet also decides firing: only the lowest alien in each column (`Alien.Column`) fires, sometimes from the column nearest the player. Each step it also calls `GameOver()` if the lowest alien's `BottomY` reaches `spaceship.TopY + loseLineOffset`.
- **Alien** spawns an `AlienBullet` when the fleet calls `Fire()`. When a `Dart` hits it, it calls `fleet.RemoveAlien(this)` and destroys itself and the dart. Any other code that destroys aliens must also go through `RemoveAlien`.
- **Spaceship** reads `Keyboard.current` directly: arrow keys move it, space fires a `Dart`. It clamps its x to the camera's visible area using its measured, asymmetric mesh extents. Input is ignored when `GameManager` isn't in the Playing state. It limits how many darts are on screen at once (by tracking the darts it spawned), and after a hit it blinks and is invulnerable for a short time. `InputSystem_Actions.inputactions` exists but nothing uses it.
- **Dart** / **AlienBullet** move by transform in `FixedUpdate` and destroy themselves once off-screen (y > 10 / y < -10). Dart has no collision handler; the Alien it hits destroys it. AlienBullet destroys itself and anything it hits except the Spaceship, which it calls `Hit()` on instead.
- **AlienCounter** is on a TMP text object under the scene's Canvas. `AlienFleet` pushes the count to it through `SetRemaining(int)`.
- **Game flow and levels:** `GameManager` plays an ordered `List<LevelData>` (ScriptableObjects with fleet/firing settings and briefing/debrief text). The states are Title → Briefing → Playing → Debrief → next Briefing … → Won (certification) → Epilogue → Title, plus Playing → Lost → Retry.
  - **Frozen screens:** every state except Playing runs with `Time.timeScale = 0`.
  - **Scene per level:** each level runs in a freshly reloaded scene. Static "pending" fields (`hasPendingStart`, `pendingState`, `pendingLevelIndex`) carry the level and start state across `SceneManager.LoadScene`.
  - **Lives:** every simulation, and every retry, starts with full lives.
  - **Run stats:** static `runLivesLost`, `runRetries` and `runTargetsDestroyed` persist across reloads. They're reset in `ResetStatics` and in `Awake` whenever there's no pending start (a new run from Play mode or the title).
  - **Certification rank:** `GameManager.GetCertificationRank()` picks the first `CertificationRank` (Inspector list, best first) whose `maxLivesLost` and `maxRetries` the run is within. Its `operatorMessage` replaces the final level's debrief text on the certification screen.
  - **Applying a level:** `AlienFleet.ApplyLevel` copies the current level's settings over its own Inspector values in `Start`. With no levels it uses its own values.
  - **Phase-2 hooks:** `LevelData.IsAnomaly` and `AlienPrefabOverride`.
- **Menu input:** all screen key presses are handled in `NierScreens.LateUpdate` (after `Spaceship.Update`, so the key that starts a level doesn't fire a dart), with an `inputDelay` so a held fire key can't skip a screen. It calls `GameManager.StartFromTitle / BeginLevel / ContinueToNextLevel / Retry / ShowEpilogue / ReturnToTitle`.
- **Typewriter:** `TypewriterText` reveals text with TMP `maxVisibleCharacters` on unscaled time. Any key completes it; Space/Enter then confirms.
- **Default levels:** `Assets/Editor/LevelDataDefaults.cs` adds **Tools → YoRHa → Create Default Levels**, which creates the three SIM assets in `Assets/Levels` (never overwriting existing ones). LevelData fields are private with read-only properties, because ScriptableObject changes made in Play mode persist to the asset. The menu fills them through the editor-only `EditorInitialize`.
- **Physics:** every moving object is moved by script, never by physics.
  - **Ship:** `Spaceship.LockRigidbodies` makes all its Rigidbodies kinematic. The scene's Spaceship has an extra non-kinematic Rigidbody from the original project, and once the ship stopped being destroyed on hit, that let bullet hits knock it away.
  - **Darts, alien bullets and aliens:** they stay non-kinematic but get `FreezeAll` constraints in `Awake`. They must not be kinematic, because kinematic–kinematic pairs don't send `OnCollisionEnter`.
  - **Lose line:** `AlienFleet` fixes it at `spaceship.TopY + loseLineOffset` in `Start`, not from the ship's live position.
- **Killing aliens:** always use `Alien.Die()`, which plays the effect, calls `fleet.RemoveAlien` and is safe to call twice. Darts and the Pod's laser both use it.
- **Pod:** a scene object that builds its body and beam from primitives in code.
  - **Charging:** it charges on `GameManager.TargetDestroyed`; kills made by the laser don't count.
  - **Firing:** E or Left Shift fires the laser, which uses `AlienFleet.CollectAliensInBeam` each `FixedUpdate`.
  - **HUD:** `PodMeter` (on the Canvas) builds the meter and the "Proposal" message, and makes itself the Canvas's first child so the screens draw over it.
- **Failure text:** per-level overrides live in `LevelData` (`Failure*` fields). Empty fields fall back to the NierScreens defaults. Anomaly levels glitch the failure title.
- **Updating level assets:** **Tools → YoRHa → Reset Default Levels (Overwrite)** rewrites the existing assets in place, keeping their GUIDs and references.
- **Models:** the ship, aliens, alien bullets and darts are drawn by code-built models (`NierModels`, using cubes plus `NierShapes` procedural prisms and octahedra). The prefabs' own renderers are disabled at runtime.
  - **NierArt:** a scene singleton with `[DefaultExecutionOrder(-200)]` that provides one unlit material per colour and caches meshes. Without it, the original visuals stay.
  - **Scale:** models sit under a "Model" root that cancels the owner's scale, so they're authored in world units. Anything that rotates must be an inner child of that root, because rotating the root itself under a non-uniformly scaled prefab shears the model.
  - **Ship:** the original capsule colliders are disabled, and the root MeshCollider gets a convex arrowhead mesh. Extents for the clamp and lose line come from the model's renderers.
  - **Aliens:** the shape depends on row % 3. `AlienVisual` handles the bob and the anomaly glitch, and moves only the model, never the alien.
  - **Shots:** each level sets a `DarkBulletChance`. Dark shots destroy darts and survive, orange shots die with the dart, and alien shots pass through each other.
- **Dialogue:** conversations are `List<DialogueLine>` entries (speaker Operator/Pod, plus text).
  - **Where they're stored:** LevelData holds the briefing, debrief and failure conversations. GameManager builds the certification conversation from the rank's `operatorMessage` and `podLine` plus a shared `certificationClosing`. Its component menu has **Reset Certification Dialogue**, because the scene keeps its own saved copy.
  - **Display:** `DialogueView` (created by NierScreens) shows a speaker label per line, the Pod's in orange. It types the lines one after another and splits them into pages to fit its area. Any key completes the page; Space/Enter turns the page or proceeds.
- **Pod voice:** every Pod line starts with a tag ("Report:", "Analysis:", "Proposal:", "Query:", "Alert:", "Correction:", "Negative.", "Affirmative."). Its tone is flat and literal. The designation is `Pod.Designation`, default "POD 217".
- **PodChatter:** on the Canvas. It shows in-play Pod commentary in a box above the Pod meter.
  - **Rules:** a global cooldown, where a higher priority can interrupt; random variants with no immediate repeats; anomaly remarks on anomaly levels.
  - **Event sources:** `GameManager` (StateChanged, LivesChanged), `Pod` (Ready, LaserFinished(kills)) and `AlienFleet` (AliensRemainingChanged, BulletFired(dark), SpeedMultiplier).
- **Story:** a NieR: Automata prequel with original characters only: the player is YoRHa No. 11 Type S, guided by Operator 17O. Don't use canon characters. Dialogue lives in the LevelData assets and the NierScreens Inspector fields.
- **NieR visual layer**, all built at runtime from code, with no prefab or scene authoring:
  - `NierStyle` (static palette and UI-building helpers)
  - `NierScreens` (on the Canvas; builds the start screen, end screen and hit flash, and listens to GameManager events)
  - `NierTextStyle` (restyles existing HUD texts)
  - `NierBackground` (on the camera; sets a solid parchment clear colour, adds a generated grid texture on a far quad, and turns off camera post-processing because the scene volume's tonemapping and vignette shift the palette)
  - `HitEffects` (singleton; square-particle bursts configured in code, using unscaled time so they still play on the frozen end screen)

  The background and effects take an optional URP `Particles/Unlit` material so the shader is included in builds. Without one they fall back to `Shader.Find`, which only reliably works in the Editor.
- Speeds and rates are per second, scaled by `Time.fixedDeltaTime`. Tuning values are `[SerializeField] private` fields. Balance decisions and their reasoning are recorded in `CODE_ISSUES.md` under "Balance Changes"; keep that section up to date when changing defaults.
- Enter Play Mode Options has domain reload disabled, so any `static` field must be reset in a `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]` method (see `GameManager.ResetStatics`, which also clears the pending-level fields, and `HitEffects.ResetStatics`). Singletons treat an existing `Instance` from a different scene as stale, because during `Retry()` the old scene's copy may still exist.

### Collision model

Collision filtering depends on **physics layers** set in `ProjectSettings/TagManager.asset` and the layer collision matrix in `ProjectSettings/DynamicsManager.asset`, not on code checks:

| Layer (index) | Used by | Does not collide with |
|---|---|---|
| Spaceship (6) | Spaceship prefab (kinematic RB) | Bullet |
| Alien (7) | Alien prefab | Alien_Bullet |
| Bullet (8) | Dart prefab | Spaceship |
| Alien_Bullet (9) | AlienBullet prefab | Alien |

All moving objects use non-trigger colliders and Rigidbodies with gravity off, and they are moved by setting `transform.position`. A new projectile or entity type needs a layer and matrix entries, or it will collide with everything.

## Editing Unity assets

`.prefab`, `.unity`, `.asset`, and `.mat` files are YAML and are hidden in VS Code by `.vscode/settings.json`. Scene and prefab wiring, such as `AlienFleet.alienPrefab` and `alienCounter`, uses GUID references from `.meta` files. Always keep a `.meta` file with its asset, and don't regenerate GUIDs. Prefer making wiring changes in the Editor over editing the YAML by hand.
